## Four Beats

1. **Name the map.** Give the PRTG Network Monitor session a short title before you touch a sensor on devices you are authorized to manage.
2. **Pin the live sensors.** Keep current alert rules on the PRTG Network Monitor board and leave unused nodes aside.
3. **Check the status.** Read the PRTG Network Monitor summary of the live status before you treat a map as ready.
4. **Close the loop.** Note which sensors are ready so the next PRTG Network Monitor visit does not start by hunting the sensor tree.

## Field Note

PRTG Network Monitor is easier to trust when the map stays smaller than the LAN it came from. A named session shows which authorized set is active, the pins show which sensors you will watch today, and the closing note tells the next shift which alert rules drive the live status. That record is short on purpose: not a copy of every packet, only the path back to devices the reader is authorized to manage.

The same loop fits a campus lab you run, a client site you are assigned, or a computer shared by two operators. Open the last PRTG Network Monitor session, confirm one sensor tree, and leave the network map easier to follow than you found it. Other programs stay where they are. PRTG Network Monitor only holds the sensor tree, the alert rules, and the handoff.

## One Real Pass

Pick a device set that already has a name and that you are authorized to manage: a lab rack, an office floor, or a short map on your desk. Open it in PRTG Network Monitor, keep only those sensors on the board, and read one live status you can point to. A pass is done when that status stays tied to the sensor tree and the unused nodes are no longer in the way. PRTG Network Monitor does not need a full rebuild of the map before it is useful.

If the pass feels crowded, the set is too wide. Drop anything that belongs to a different job and leave it out of this workspace. The next pass can have its own title. What matters is that this one stays readable from the first sensor to the last alert rule, with the summary still matching the network map on that desk.
